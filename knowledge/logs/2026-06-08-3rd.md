## 3. 公式ドキュメント調査結果

### best-practices.md（新規取得）

**主要な知見（前回未収録）**:

1. **コンテキストウィンドウが最重要リソース**
   - 全会話・読み込みファイル・コマンド出力を保持
   - 満杯に近づくと性能劣化
   - カスタムステータスラインでコンテキスト使用量をリアルタイム追跡推奨

2. **検証手段を与える原則**
   - `pass/fail` シグナルを返すもの（テスト、ビルド、スクリーンショット比較）を提供
   - 段階的ゲート: 単一プロンプト → `/goal` 条件 → Stop フック（最大8回ブロック） → 検証サブエージェント

3. **Explore→Plan→Implement→Commit 4フェーズ**
   - Plan Mode（`Ctrl+G`）でエクスプローラーとコーダーを分離
   - 小さな変更は直接実行（オーバーヘッド回避）

4. **CLAUDE.md 設計原則（詳細）**:
   - `/init` で初期ファイル自動生成（`CLAUDE_CODE_NEW_INIT=1` でインタラクティブモード）
   - **200行以下**を目標。超えると遵守率低下
   - HTMLコメント `<!-- -->` はコンテキストから自動除去（メンテナー注記用）
   - `@path/to/import` 構文で他ファイルをインポート（最大4ホップ）
   - `AGENTS.md` との相互運用: `@AGENTS.md` インポートまたはシンリンクで統一

5. **スキル vs CLAUDE.md の使い分け**:
   - CLAUDE.md: 全セッションで常時必要な情報
   - スキル: 特定ドメイン・ワークフローの知識（必要時のみロード）

6. **フック活用**:
   - CLAUDE.md 指示は advisory（勧告的）
   - フックは deterministic（決定論的保証）
   - `PreToolUse` フックでアクションを確実にブロック

### agent-teams.md（新規詳細取得）

**サブエージェント vs エージェントチームの比較**:

| 項目 | サブエージェント | エージェントチーム |
|------|---------------|----------------|
| コンテキスト | 独自、結果だけ親に返す | 独自、完全独立 |
| コミュニケーション | 親への一方向のみ | チームメイト間の直接メッセージ |
| 調整 | 親が全作業管理 | 共有タスクリストで自己調整 |
| 最適用途 | 結果だけ重要な集中タスク | 議論・協調が必要な複雑作業 |
| トークンコスト | 低（結果のみ親コンテキストに） | 高（各チームメイトが別Claudeインスタンス） |

**エージェントチームのアーキテクチャ**:
- チームリード: メインセッション（チーム生成・スポーン・調整）
- チームメイト: 独立した Claude Code インスタンス
- タスクリスト: `~/.claude/tasks/{team-name}/`（ファイルロックで競合防止）
- メールボックス: エージェント間メッセージング

**フック（エージェントチーム専用）**:
- `TeammateIdle`: チームメイトがアイドルになる前に実行（exit 2 でフィードバック送信・継続）
- `TaskCreated`: タスク作成時（exit 2 で作成防止）
- `TaskCompleted`: タスク完了時（exit 2 で完了防止・フィードバック）

**表示モード**:
- `"auto"`: tmuxセッション内なら split-pane、それ以外は in-process
- `"in-process"`: 全チームメイトをメインターミナル内で実行
- `"tmux"`: tmux または iTerm2 で各チームメイトを別ペインに表示

## 4. AI オーケストレーション最適化（抽出）

### オーケストレーター/ワーカーの責務分離

1. **最小権限のツール制限**: `tools` フィールドでワーカーサブエージェントが使えるツールを明示制限
   - 例: doc-reviewer に `Read`/`Grep` のみ → 意図しないファイル変更を防止

2. **コンテキスト渡し設計の原則**:
   - 親→サブエージェントへ渡せるのは **Agent ツールのプロンプト文字列のみ**
   - ファイルパス・エラーメッセージ・決定事項を明示的にプロンプトに含める
   - サブエージェントが読んだファイル内容は親に返らない（要約のみ）

3. **並列 vs 直列の判断基準**:
   - **並列適合**: 同一ファイルを編集しない独立タスク、競合する仮説の検証、複数ドメインのリサーチ
   - **直列適合**: 依存関係あり・同一ファイル編集・多くの前提条件
   - エージェントチーム: `TaskCompleted` フックで依存タスクを自動アンブロック

4. **ループ・再試行・エスカレーション**:
   - Stop フック: exit code 2 で最大8回ブロック（`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で上書き可）
   - `additionalContext` フックでブロックせずにフィードバックだけ送る
   - `/goal` 条件: 別の evaluator モデルが毎ターン後に条件チェック、満たされるまで継続
   - `TeammateIdle` フック: チームメイトに追加作業を促す

5. **コスト最適化（タスク別モデル割り当て）**:
   - `AgentDefinition.model` で各サブエージェントにモデルを個別指定
   - リサーチ・読み取り専用 → `sonnet`（安価）
   - 重要なセキュリティレビュー → `opus`（高精度）
   - バックグラウンドサイドクエリ → `haiku`（最安）
   - `fallbackModel` 設定（最大3つ）でプライマリ障害時の代替モデルを自動選択

## 5. CLAUDE.md ベストプラクティス（抽出）

### 書くべき内容・書かない内容

**書くべき**:
- Bash コマンド（Claude が推測できないもの）
- デフォルトと異なるコードスタイルルール
- テスト手順と優先するテストランナー
- リポジトリ運用（ブランチ命名、PR規約）
- プロジェクト固有のアーキテクチャ決定
- 開発環境の癖（必要な環境変数）
- よくあるハマりどころや非自明な挙動

**書かない**:
- Claude がコードを読めば分かること
- Claude が既知の標準言語規約
- 詳細な API ドキュメント（URLリンク推奨）
- 頻繁に変わる情報
- 長い説明や学習コンテンツ
- ファイルごとのコードベース説明
- "クリーンなコードを書く" 等の自明なもの

### グローバル（`~/.claude/`）とプロジェクト（`.claude/`）の使い分け

| スコープ | 用途 | 共有 |
|---------|------|------|
| `~/.claude/CLAUDE.md` | 全プロジェクト共通の個人設定 | 自分のみ |
| `~/.claude/rules/` | 個人的な全プロジェクトルール | 自分のみ |
| `./CLAUDE.md` | チーム共通の標準（バージョン管理） | チーム |
| `./.claude/CLAUDE.md` | 同上（.claude ディレクトリ内） | チーム |
| `./CLAUDE.local.md` | 個人的なプロジェクト設定（.gitignore） | 自分のみ |
| `./.claude/rules/` | トピック別ルール（パス限定ルール対応） | チーム |

### 効果的なセクション構成

- **短く**: 200行以下が目標
- **マークダウン構造**: ヘッダー+�条書きで整理
- **具体的**: "2スペースインデント" ではなく "2-space indentation"
- **テスト**: CLAUDE.md 変更後は実際の挙動で効果確認
- **強調**: 重要ルールには "IMPORTANT" や "YOU MUST" を使用
- **定期的にプルーニング**: 古い・矛盾するルールを取り除く

### 自動読み込みの仕組みと優先順位

```
起動時ロード:
1. /Library/.../CLAUDE.md（管理ポリシー、除外不可）
2. ~/.claude/CLAUDE.md（ユーザー全プロジェクト）
3. ~/.claude/rules/*.md（ユーザー全プロジェクトルール）
4. 現在ディレクトリから上に向かってすべての CLAUDE.md
5. ./CLAUDE.md または ./.claude/CLAUDE.md
6. ./CLAUDE.local.md

遅延ロード:
- サブディレクトリの CLAUDE.md → そのディレクトリのファイルを読んだ時
- .claude/rules/ のパス限定ルール → マッチするファイルを操作した時

Auto Memory:
- ~/.claude/projects/<project>/memory/ に Claude が自動書き込み
- 最初の200行または25KB をセッション開始時にロード
```
