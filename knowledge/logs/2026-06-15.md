## 2. 公式ドキュメントから新規確認した情報

### 2-1. best-practices.md — 新規詳細確認

**コンテキスト管理の核心メッセージ（公式明文化）:**
> "Most best practices are based on one constraint: Claude's context window fills up fast, and performance degrades as it fills."

**検証ループ設計（4段階ゲート）:**
1. **プロンプト内**: `run the tests after implementing` のように同一プロンプトで検証指示
2. **セッション横断**: `/goal` 条件 → 評価エージェントが毎ターン後に再チェック
3. **決定論的ゲート**: Stop フック（スクリプト実行）→ 8連続ブロックでオーバーライド
4. **セカンドオピニオン**: 検証サブエージェント or ダイナミックワークフロー

**Explore → Plan → Implement → Commit ワークフロー（公式再確認）:**
- プランモードで Explore/Plan を分離
- `Ctrl+G` でプランをテキストエディタで直接編集可能
- 小さなタスクではプラン不要（一文で差分説明できる場合はスキップ推奨）

### 2-2. subagents.md — ビルトインサブエージェント詳細確認

**ビルトインサブエージェント一覧（公式）:**

| エージェント | モデル | 用途 |
|---|---|---|
| **Explore** | Haiku（高速・低レイテンシ） | ファイル探索・コード検索（CLAUDE.md スキップ） |
| **Plan** | 親会話を継承 | プランモード中のリサーチ（CLAUDE.md スキップ） |
| **general-purpose** | 親会話を継承 | 探索と変更を伴う複合タスク |
| **statusline-setup** | Sonnet | `/statusline` 実行時 |
| **claude-code-guide** | Haiku | Claude Code 機能の質問時 |

**重要な制約:**
- Explore / Plan は CLAUDE.md と親セッションの git status をスキップ（高速化のため）
- 他のサブエージェントは両方読み込む
- 非インタラクティブモード / Agent SDK では `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` で全ビルトイン無効化

**サブエージェント設定オプション（/agents コマンド経由）:**
1. 識別子・説明・システムプロンプトを Claude が自動生成
2. ツール選択（読み取り専用 / 全ツール / カスタム）
3. モデル選択（Haiku / Sonnet / 親継承）
4. カラー識別
5. **メモリ設定**: `User scope` → `~/.claude/agent-memory/` に永続メモリ / `None` → 非永続

**フォークサブエージェント（`context: fork`）:**
- 現在の会話をコピーしてサブエージェントを起動
- 親コンテキストが大きい場合、フォークでコンテキストを引き継ぎながら分離実行

### 2-4. memory.md — CLAUDE.md 設計詳細

**CLAUDE.md の自動読み込み仕組み（公式確認）:**

ディレクトリツリーを作業ディレクトリから上向きに走査:
- `foo/bar/` で起動 → `foo/bar/CLAUDE.md`、`foo/CLAUDE.md`、各 `CLAUDE.local.md` を読み込む
- ファイル間は連結（上書きではない）
- ファイルシステムルートから作業ディレクトリに向かって順序付け（近いものが後に読まれる）
- `CLAUDE.local.md` は各ディレクトリの最後に追記
- サブディレクトリの CLAUDE.md は起動時には読み込まず、そのディレクトリのファイル読み取り時に読み込み

**CLAUDE.md ファイルのスコープ一覧:**

| スコープ | 場所 | 用途 |
|---|---|---|
| **Managed policy** | macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md`<br>Linux/WSL: `/etc/claude-code/CLAUDE.md`<br>Windows: `C:\Program Files\ClaudeCode\CLAUDE.md` | 組織全体（IT/DevOps 管理） |
| **User instructions** | `~/.claude/CLAUDE.md` | 個人の全プロジェクト共通設定 |
| **Project instructions** | `./CLAUDE.md` or `./.claude/CLAUDE.md` | チーム共有設定 |
| **Local instructions** | `./CLAUDE.local.md`（.gitignore 推奨） | 個人プロジェクト固有設定 |

**効果的なCLAUDE.md の記述原則（公式）:**
- **サイズ目標**: ファイルあたり 200行以下（コンテキスト消費・遵守率に影響）
- **構造**: マークダウンヘッダー・箇条書きで関連指示をグループ化
- **具体性**: 検証可能な指示（"2スペースインデント" > "適切にフォーマット"）
- **一貫性**: 矛盾する指示がある場合、Claude が恣意的に選択する可能性
- **HTMLコメント**: `<!-- コメント -->` は context に注入前に自動除去（メンテナー向けメモに活用）

**`@path` インポート:**
- 相対・絶対パス両対応
- 最大4ホップの再帰インポート可能
- `CLAUDE.local.md` でプライベート設定を分離（gitignore 推奨）

**`.claude/rules/` でのルール整理:**
```
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── code-style.md
│       ├── testing.md
│       └── security.md
```
- `paths` frontmatter でファイルパス限定ルールを定義
- パス限定ルールは該当ファイル操作時のみコンテキストに読み込み（コンテキスト節約）

**AGENTS.md 相互運用:**
```markdown
@AGENTS.md

## Claude Code
Use plan mode for changes under `src/billing/`.
```

### 2-5. agent-teams.md — エージェントチーム詳細

**エージェントチームの特徴（公式）:**
- サブエージェントとの最大の違い: **チームメイト同士が直接メッセージング可能**
- 共有タスクリストによる自己調整
- 実験的機能（デフォルト無効）: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`

**サブエージェント vs エージェントチームの使い分け:**

| 観点 | サブエージェント | エージェントチーム |
|---|---|---|
| コミュニケーション | 結果を親に返すのみ | チームメイト同士で直接通信 |
| 調整方法 | 主エージェントが全管理 | 共有タスクリストで自律調整 |
| 最適用途 | 結果だけが重要な集中タスク | 議論・協力が必要な複雑作業 |
| トークンコスト | 低（結果のみ返却） | 高（各チームメイトが独立インスタンス） |

**移行判断基準:** 並列サブエージェントがコンテキスト限界に達するか、サブエージェント同士が通信が必要になったらエージェントチームへ移行

**計画承認フロー（プラン承認必須モード）:**
1. チームメイトが読み取り専用プランモードで作業
2. 計画完成時にリードへ承認リクエスト送信
3. リードが承認 or フィードバック付き却下
4. 却下時はプランモードのまま修正・再送信
5. 承認後にプランモード終了・実装開始

**表示モード:**
- `in-process`: 全チームメイトがメインターミナル内（Shift+Down でサイクル）
- `split panes`: tmux または iTerm2 で各チームメイトが独立ペイン
- デフォルト `auto`: tmux セッション内または iTerm2 の場合は split panes

| **MCP** | 外部サービス接続 | 外部データ・アクション |
| **フック** | イベントトリガー自動化 | 毎回確実に実行したい自動化 |

**段階的セットアップの推奨手順:**
1. Claude がコンベンションを2回間違えたら → CLAUDE.md に追加
2. 同じプロンプトを繰り返し入力するなら → スキルとして保存
3. ブラウザからデータをコピーしているなら → MCP サーバー接続
4. 側タスクが会話を大量出力で埋めるなら → サブエージェント経由
5. 毎回自動実行したいなら → フック作成
6. 別リポジトリでも同じ設定が必要なら → プラグインとしてパッケージ化

### 2-8. mcp.md — MCP 最新機能

**MCP サーバータイプ（2026年時点）:**
1. **HTTP (streamable-http)**: リモートサーバー推奨（`claude mcp add --transport http`）
2. **SSE**: 非推奨（HTTP へ移行推奨）
3. **stdio**: ローカルプロセス（`CLAUDE_PROJECT_DIR` 環境変数が自動設定）

**新機能:** `CLAUDE_PROJECT_DIR` がサーバープロセス環境に自動設定されるようになった（プロジェクト相対パス解決が容易に）

## 4. AI オーケストレーション最適化 — 公式ドキュメントからの抽出

### 4-1. オーケストレーター / ワーカーの責務分離

**公式推奨パターン:**
```
Command → Agent（オーケストレーター） → Skill（ワーカー）
```

- **オーケストレーター（主エージェント）**: タスク分解・サブエージェント起動・結果統合
- **ワーカー（サブエージェント）**: 単一タスク実行・結果要約して返却
- **Explore サブエージェント**: 読み取り専用・Haiku モデル・CLAUDE.md スキップ（コスト最適化）
- **Plan サブエージェント**: 読み取り専用・プランモード中のリサーチ担当

### 4-2. エージェント間のコンテキスト受け渡し設計

- **サブエージェント**: 親コンテキストを継承しない（独立コンテキストウィンドウ）→ 結果のみ親に返却
- **フォークサブエージェント（`context: fork`）**: 親コンテキストをコピーして独立実行
- **エージェントチーム**: 共有タスクリスト経由で調整・直接メッセージング可能
- **スキルプリロード**: `skills:` フィールドでサブエージェントにスキルを事前読み込み

### 4-3. 並列 vs 直列の使い分け判断基準

**並列が有効なケース:**
- 調査・レビュー（複数観点を同時に探索）
- 独立した新モジュール / 機能
- 競合仮説のデバッグ
- クロスレイヤー調整（フロントエンド・バックエンド・テストを別々のエージェントが担当）

**直列（単一セッション / サブエージェント）が有効なケース:**
- 順序依存タスク
- 同一ファイルへの編集
- 依存関係が多い作業

**エスカレーション判断:**
- 並列サブエージェントがコンテキスト限界に達したら → エージェントチームへ移行
- サブエージェント同士の通信が必要になったら → エージェントチームへ移行

### 4-4. ループ・再試行・エスカレーション設計

**品質ゲート4層（公式）:**
1. **プロンプト内検証**: `run tests after implementing`
2. **`/goal` 条件**: 評価エージェントが毎ターン後にチェック・Claude が通過まで継続
3. **Stop フック**: スクリプトでゲート → 8連続ブロックで強制終了
4. **検証サブエージェント**: 実装エージェントとは別の新鮮なモデルが結果を反証

**Stop / SubagentStop フックの `additionalContext`:**
- エラーなしでターンを継続しながら Claude にフィードバックを渡せる

**`PermissionDenied` フック（新規確認）:**

## 5. CLAUDE.md ベストプラクティス — 公式ドキュメントからの抽出

### 5-1. CLAUDE.md に書くべき内容 vs 書かない内容

**書くべき内容:**
- ビルドコマンド・テストコマンド
- コーディングコンベンション・命名規則
- プロジェクトアーキテクチャの概要
- "常に X をする" ルール
- 新メンバーが作業開始するのに必要なコンテキスト
- Claude が2回同じ間違いをした内容
- コードレビューでキャッチされた内容

**書かない内容（代替手段あり）:**
- 複数ステップのプロシージャ → **スキル**へ
- コードベースの一部にしか関係しない内容 → **パススコープルール**（`.claude/rules/`）へ
- 一度限りの訂正 → チャットで直接指示
- 任意の外部データ・タスク固有の参照資料 → **スキル**へ

### 5-2. グローバル（~/.claude/）とプロジェクト（.claude/）の使い分け

**グローバル (`~/.claude/CLAUDE.md`):**
- 個人の全プロジェクト共通設定
- コードスタイル設定・個人ツールのショートカット
- チームで共有しないもの

**プロジェクト (`.claude/CLAUDE.md` または `CLAUDE.md`):**
- チーム共有設定（バージョン管理で共有）
- プロジェクトアーキテクチャ・コーディング標準・共通ワークフロー

**ローカル (`CLAUDE.local.md`):**
- 個人プロジェクト固有設定（gitignore 推奨）
- サンドボックスURL・優先テストデータ

**組織 (Managed Policy):**
- 全ユーザーへの強制適用（IT/DevOps 管理）
- 会社コーディング標準・セキュリティポリシー

### 5-3. 効果的なセクション構成・記述スタイル

**推奨構成例:**
```markdown
# プロジェクト概要
[1-2文での説明]

# ビルド・テストコマンド
- ビルド: `npm run build`
- テスト: `npm test`

# コーディング規約
- 2スペースインデント
- TypeScript strict モード

# アーキテクチャ
[プロジェクト構造の概要]

# ワークフロー
[よく使うパターン]
```

**記述スタイルのポイント:**
- 200行以下を目標
- HTMLコメント `<!-- -->` でメンテナーメモを追加（コンテキストに注入されない）
- `@path` インポートで関連ファイル参照
- `.claude/rules/` でパス限定ルールを分離
- `CLAUDE_CODE_NEW_INIT=1` で `/init` のインタラクティブモードを有効化

### 5-4. 自動読み込みの仕組みと優先順位

**読み込み順序（優先順位低→高）:**
1. Managed Policy CLAUDE.md（組織全体）
2. `~/.claude/CLAUDE.md`（ユーザー）
3. ファイルシステムルート → 作業ディレクトリに向かって各 CLAUDE.md
4. `./.claude/rules/`（パス非限定ルール）
5. `./CLAUDE.local.md`（ローカル個人設定、最後）

**サブディレクトリの CLAUDE.md:**
- 起動時には読み込まない
- Claude がそのサブディレクトリのファイルを読み取る時に初めて読み込み

**コンパクト後の動作（前回確認済み）:**
- プロジェクトルート CLAUDE.md は自動再注入
- サブディレクトリの CLAUDE.md は非自動
