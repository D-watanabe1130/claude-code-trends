### best-practices.md（新規詳細確認）

**コンテキスト管理の核心原則**（初めての詳細確認）:
1. **コンテキストウィンドウが最重要リソース**: パフォーマンス劣化の主因。コンテキスト可視化ウォークスルーが公式提供
2. **検証ループの構築が必須**: テスト/ビルド/スクリーンショット等の自動チェックがない場合、ユーザーが検証ループになる
3. **検証強度の4段階**:
   - プロンプト内検証（その場で実行）
   - `/goal` 条件（毎ターン後に評価エージェントがチェック）
   - Stop フック（スクリプトゲート、8連続ブロックで強制終了）
   - 検証サブエージェント（別モデルが反証）
4. **Explore → Plan → Implement → Commit** の4フェーズワークフロー（plan mode）
5. **CLAUDE.md の明確な判断基準**（表形式）:
   - ✅ 含めるべき: Bash コマンド、コードスタイルルール、テスト指示、リポジトリエチケット、アーキテクチャ決定、開発環境の特殊事項
   - ❌ 含めない: Claude がコードから推測できること、標準的な言語規約、変化する情報、長い説明・チュートリアル

**フックイベント補足**:

- `UserPromptExpansion`: ユーザータイプコマンドのプロンプト展開前に発火（ブロック可能）
- `PermissionDenied`: Auto Mode でのツール拒否時に発火。`{retry: true}` を返すと再試行を許可
- `PostToolBatch`: 並列ツール呼び出し一括完了後、次のモデル呼び出し前に発火
- `MessageDisplay`: アシスタントメッセージテキストのストリーミング中に発火
- `TeammateIdle`: エージェントチームのチームメイトがアイドル直前に発火
- `InstructionsLoaded`: CLAUDE.md / `.claude/rules/*.md` のロード時に発火（セッション開始 + 遅延ロード両方）
- `PreCompact` / `PostCompact`: コンテキストコンパクション前後に発火

**フック解決フロー**（新規確認）:
1. イベント発火 → JSON をサブプロセスの stdin に送信
2. matcher チェック（ツール名マッチ）
3. `if` 条件チェック（オプション、パラメータマッチ）
4. フックハンドラー実行
5. 結果処理（Claude Code が stdout の JSON を読んでアクション）

**フックタイプ**: command / HTTP endpoint / LLM prompt

### memory.md（新規詳細確認）

**CLAUDE.md vs Auto Memory 比較**:

| 観点 | CLAUDE.md | Auto Memory |
|------|-----------|-------------|
| 誰が書くか | ユーザー | Claude（自動） |
| 内容 | 指示・ルール | 学習・パターン |
| スコープ | プロジェクト/ユーザー/組織 | リポジトリ単位（Worktree 間共有） |
| ロード | 毎セッション | 毎セッション（最初の200行 or 25KB） |

**CLAUDE.md スコープ別ロード順序**（低優先度→高優先度）:

| スコープ | パス | 目的 |
|---------|------|------|
| Managed policy | macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md`<br>Linux/WSL: `/etc/claude-code/CLAUDE.md`<br>Windows: `C:\Program Files\ClaudeCode\CLAUDE.md` | 組織全体（IT/DevOps 管理） |

**CLAUDE.md 記述原則**:
- **200行以下**目標（超えると遵守率低下）

- `claudeMdExcludes` でモノレポの不要 CLAUDE.md スキップ
- `CLAUDE_CODE_NEW_INIT=1` でインタラクティブ `/init` モード（CLAUDE.md / skills / hooks を選択的作成）

**Skill vs Subagent の判断基準**（公式詳細）:
- **Skill**: コンテキストウィンドウに追加される（メインウィンドウを消費）。参照資料 or 呼び出し型ワークフロー
- **Subagent**: 独立コンテキストウィンドウ使用。多ファイル読み込み、並列作業、中間作業が不要な場合
- **Subagent → Agent Teams の移行点**: 並列 Subagent でコンテキスト限界に達した場合 or Subagent 間での通信が必要な場合

**段階的セットアップ推奨トリガー**:
1. Claude が同じ間違いを2回 → CLAUDE.md 追記
2. 同じプロンプトを繰り返し入力 → Skill 化
3. 同じ手順書をチャットに3回貼り付け → Skill 化
4. ブラウザタブからデータをコピーし続ける → MCP サーバー接続
5. 記号定義場所の探索が遅い → Code Intelligence プラグイン
6. サイドタスクが会話を汚染 → Subagent にルーティング
7. 毎回必ず実行したいアクション → Hook 作成
8. 別のリポジトリでも同じセットアップが必要 → Plugin 化
