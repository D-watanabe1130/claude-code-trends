## 前回比較：新たに判明した変更点

### 【重要】フックシステムの大幅拡張（公式ドキュメント更新）

前回は `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd`, `InstructionsLoaded`, `UserPromptExpansion` を記録していたが、今回の調査で **さらに多くのフックイベントが公式ドキュメントに追加**されていることが判明。

#### 新確認フックイベント（前回未記録）

| イベント | 概要 | ブロック可否 |
|---------|------|----------|
| `Setup` | `--init-only`, `--init`, `--maintenance` 起動時 | - |
| `PermissionRequest` | 権限ダイアログ表示時。自動承認/拒否が可能 | 可 |
| `PermissionDenied` | Auto Classifierが拒否した時。`{retry: true}` でリトライ | - |
| `PostToolBatch` | 並列ツール呼び出しの後（次のモデル呼び出し前） | 可 |
| `SubagentStart` | サブエージェント起動時 | - |
| `SubagentStop` | サブエージェント終了時 | 可 |
| `TaskCreated` | TaskCreate でタスク生成時。ロールバック可能 | 可 |
| `TaskCompleted` | タスク完了時 | 可 |
| `TeammateIdle` | Agent Team のチームメイトがアイドル状態に | 可 |
| `StopFailure` | APIエラーでターン終了時（rate_limit, billing_error 等） | - |
| `CwdChanged` | 作業ディレクトリ変更時 | - |
| `ConfigChange` | 設定ファイル変更時 | 可（policyは除く） |
| `PreCompact` | コンテキスト圧縮前 | 可 |
| `PostCompact` | 圧縮完了後 | - |
| `Notification` | Claude Codeが通知送信時 | - |
| `Elicitation` | MCPサーバーがユーザー入力を要求時 | 可 |
| `ElicitationResult` | ユーザーがMCP elicitationに応答後 | 可 |
| `WorktreeCreate` | Worktree生成時。フックでパスを指定可能 | - |
| `WorktreeRemove` | Worktree削除時 | - |

#### 新フックオプション（前回未記録）

```json
{
  "type": "command",
  "command": "background-monitor.sh",
  "once": true,          // セッションに一度だけ実行
  "asyncRewake": true    // バックグラウンド実行 + exit code 2でClaudeを起動
}
```

- **`once: true`**: フックをセッション中に1回だけ実行。`SessionStart` 系の初期化タスクに最適。
- **`asyncRewake: true`**: バックグラウンド実行し、exit code 2 でClaude を再起動（stderrはsystem reminderとして表示）。長時間バックグラウンドモニタリングに使用。

#### HTTPフックの`allowedEnvVars`（前回未記録）

```json
{
  "type": "http",
  "url": "http://localhost:8080/hooks",
  "headers": {
    "Authorization": "Bearer $MY_TOKEN"
  },
  "allowedEnvVars": ["MY_TOKEN"]
}
```

ヘッダー内の環境変数展開が可能に。外部エンドポイントへの認証付きフック連携がシンプルに。

#### MCPツールフックの`input`テンプレート（前回未記録）

```json
{
  "type": "mcp_tool",
  "server": "my_server",
  "tool": "security_scan",
  "input": { "file_path": "${tool_input.file_path}" }
}
```

ツール入力をMCPフックに引き渡すテンプレート構文が明示的に文書化。

#### `disableAllHooks: true` 設定（前回未記録）

全フックを一括無効化できる設定。マネージドポリシー階層を尊重する。

### 【重要】CLAUDE.md の新機能

#### AGENTS.md 相互運用性（前回未記録）

Claude Code は `CLAUDE.md` を読む（`AGENTS.md` は読まない）。他のコーディングエージェントと共存する場合：

```markdown
<!-- CLAUDE.md -->
@AGENTS.md

## Claude Code 固有設定
src/billing/ の変更はplan modeを使うこと。
```

または シンボリックリンクで対応：
```bash
ln -s AGENTS.md CLAUDE.md  # Windowsでは不可
```

`/init` 実行時は `AGENTS.md`（および `.cursorrules`, `.windsurfrules`）を自動認識して取り込む。

#### HTMLコメントのコンテキスト除外（前回未記録）

CLAUDE.md 内のブロックレベルHTMLコメントはコンテキスト注入前に**自動除去**される。

```markdown
<!-- メンテナー向けノート: このセクションは2026Q2に廃止予定 -->
- 実際の指示はここ
```

コードブロック内のコメントは保持される。メンテナー向けの内部メモをトークンを使わずに残せる。

#### `claudeMd` キー（managed-settings.json）（前回未記録）

```json
{
  "claudeMd": "常に `make lint` をコミット前に実行すること。\nmainへの直接pushは禁止。"
}
```

組織全体設定ファイルに CLAUDE.md の内容を直接埋め込める。ファイル配布が不要に。

### メモリシステムの新機能

#### `autoMemoryDirectory` 設定（前回未記録）

```json
// ~/.claude/settings.json
{
  "autoMemoryDirectory": "~/my-custom-memory-dir"
}
```

Auto Memory の保存場所をカスタマイズ可能。絶対パスまたは `~/` 始まりのパスが必須。プロジェクト・ローカル設定からは不可（セキュリティ上の理由）。

#### サブエージェントの独自Auto Memory（前回未記録）

サブエージェントも独自の Auto Memory を持てることが公式ドキュメントに明記された。詳細は `/en/sub-agents#enable-persistent-memory` を参照。

#### `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` 環境変数（前回未記録）

```bash
CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 claude --add-dir ../shared-config
```

`--add-dir` で追加したディレクトリの CLAUDE.md・rules もロードするフラグ。デフォルトでは追加ディレクトリの CLAUDE.md は読まれない。

### 新コマンド・UI 機能

#### `/btw` コマンド（前回未記録）

サイドクエスチョン機能。回答が**会話履歴に残らない**ディスミス可能なオーバーレイとして表示される。

```text
/btw このファイルのライセンスは？
```

コンテキストを汚染せずに詳細を確認したい時に有効。

#### `AskUserQuestion` ツールパターン（前回未記録・公式推奨）

大型フィーチャーの際にClaude自身がユーザーにインタビューさせるパターンが公式ベストプラクティスに掲載：

```text
[ブリーフ説明]を作りたい。AskUserQuestion ツールを使って詳細にインタビューしてほしい。
技術実装、UI/UX、エッジケース、懸念事項、トレードオフを聞いてほしい。
一通り終わったら完全な仕様を SPEC.md に書いてほしい。
```

実装は別セッションで開始することが推奨。

#### Chrome拡張機能でのUI検証（前回未記録）

`Claude in Chrome` 拡張機能でUI変更を自動検証。新しいタブを開き、UIをテストし、コードが動くまで反復する。

#### `/sandbox` による OS レベル分離（前回未記録・明示化）

ファイルシステム・ネットワークアクセスを制限するOS レベルのサンドボックス。Auto Mode、Permission Allowlists と並ぶ第3の権限管理手段として公式ガイドで明示。

### 環境変数の新規文書化

| 環境変数 | 用途 |
|---------|-----|
| `CLAUDE_EFFORT` | 現在のエフォートレベル（フック内で参照可能） |
| `$CLAUDE_CODE_REMOTE` | Webセッションでは `"true"`、CLIでは未設定 |
| `CLAUDE_ENV_FILE` | 環境変数を永続化するファイル（SessionStart等で利用） |

`$CLAUDE_CODE_REMOTE` でWebセッションとCLIセッションを判別できる。フック内でCIとローカルの動作を分岐させる際に有用。

### セッション管理の補足（公式ガイド更新確認）

#### `/compact <instructions>` の強化

```text
/compact APIの変更部分にフォーカスして
```

圧縮時にフォーカスする内容を指定できる。前回の記録では `/compact` コマンドとして存在は把握していたが、引数指定パターンが公式ベストプラクティスに明示された。

#### `--append-system-prompt` フラグ（前回未記録）

```bash
claude --append-system-prompt "必ずJSDocを書くこと"
```

スクリプトや自動化向けにシステムプロンプトレベルの指示を追加。毎回フラグで渡す必要があるためインタラクティブ用途より自動化向き。

### 新たに公式化されたアンチパターン（追加項目）

| アンチパターン | 対処法 |
|------------|------|
| CLAUDE.md が肥大化しすぎ | パススコープルール（`.claude/rules/`）に移動、使わないルールは削除 |

- **200行以下が目標**（変わらず）
- 超えるならパススコープルール（`.claude/rules/`）で特定ファイルのみロード
- `@path/to/import` インポートは組織化に役立つが、コンテキスト削減にはならない（起動時に展開される）

## 今週のまとめ

### 変化の大きかった領域

1. **フックシステム**: イベント種別がほぼ倍増。特に `asyncRewake`, `once`, `PermissionRequest`, `PermissionDenied`, `PostToolBatch`, `WorktreeCreate/Remove`, `Elicitation` は新しいユースケースを開く
2. **AGENTS.md 互換**: 複数エージェントフレームワーク共存の公式ガイドが整備された
3. **CLAUDE.md のHTMLコメント除去**: トークンを使わずにメンテナーノートを残せる実用的機能
4. **サブエージェントのAuto Memory**: サブエージェントが学習・記憶できるようになり、専門エージェントがプロジェクトを跨いで知識を蓄積できる
5. **/btw コマンド**: コンテキストを汚さない軽量な確認手段

### 変化の小さかった領域

- バージョン情報: CHANGELOG 取得失敗のため不明（前回: v2.1.142）
- エコシステム（リポジトリスター等）: GitHub アクセス失敗のため不明
- クロスモデルワークフロー: 変化なし（推定）
