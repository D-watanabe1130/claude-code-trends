## 新機能・変更詳細

### v2.1.214: Auto Memory に `modified` タイムスタンプ

Claude がフロントマターを含む memory ファイルを書き込む際、Claude Code が `modified` フィールドに ISO 8601 形式のタイムスタンプを自動記録するようになった。

```yaml
---
modified: 2026-07-27T09:15:00Z
---
```

- ファイルがどれだけ古いかが人間にも Claude にも一目でわかる
- 既存フロントマターがあれば次回書き込み時に自動付与される
- フロントマターのないファイルには追加されない
- v2.1.214 以降が必要

### v2.1.214: フックの exit 2 挙動修正

`PostToolUse` などのフックで exit 2 が JSON 検証失敗と組み合わさったとき、以前は JSON エラーが優先されてブロック動作が無視されていたが、v2.1.214 以降は exit 2 が確実にブロックとして扱われる。

### v2.1.216: `/memory` がノンブロッキングに

VS Code など GUI エディタでメモリファイルを開いた際、以前はファイルを閉じるまでセッションが一時停止していた。v2.1.216 以降は別ウィンドウでファイルを開いたままセッションを継続できる（Vim 等ターミナルエディタは従来通り占有）。

### v2.1.216: `isolation: worktree` の Bash コマンド自体のチェック

これまで `isolation: worktree` はワーキングディレクトリのみチェックしていたが、v2.1.216 以降は Bash コマンドの内容自体もチェックし、以下のパターンでメインチェックアウトにアクセスするコマンドを失敗させる:

- `git -C <main-checkout-path>`
- `--git-dir=<main-checkout-path>`
- `GIT_DIR` / `GIT_WORK_TREE` 環境変数でのリダイレクト
- `cd <main-checkout-path> && ...` のチェーンコマンド

複雑すぎて解析できないコマンドも、分割するよう求めるエラーで失敗する（PowerShell コマンドにはワーキングディレクトリチェックのみ適用）。

### v2.1.217: パス限定ルールのブレース展開に予算制限

`.claude/rules/` のパス限定ルールで `paths` フィールドのブレース展開が、ルール全体で **1,000 展開パターン / 4 MiB** の予算を超えた場合、超過分はブレース未展開のリテラルとして扱われ（事実上マッチなし）、他のパターンは継続動作する。

```yaml
# 例: {a,b}/{c,d}/*.{ts,tsx} → 8 パターン（予算内）
---
paths:
  - "src/**/*.{ts,tsx}"
  - "tests/**/*.test.{ts,tsx}"
---
```

v2.1.217 以前は多数のブレースグループがあるとCLIが起動時にハングまたはクラッシュすることがあった。

### v2.1.218: サブエージェントフロントマターフックへのワークスペーストラスト

サブエージェントのフロントマターで定義したフックが、ワークスペーストラストダイアログの対象に組み込まれた（プロジェクト設定のフックと同様の承認フロー）。

## ドキュメント大幅更新: 新規文書化された機能

以下はドキュメントに新たに記載された機能群（バージョン特定は困難だが、今週初めて確認）。

### `CLAUDE_CODE_NEW_INIT=1`: 多段階 `/init` フロー

この環境変数を設定した状態で `/init` を実行すると、対話型の多段階フローが起動する:

1. どのアーティファクト（CLAUDE.md / スキル / フック）を設定するか確認
2. サブエージェントでコードベースを探索
3. フォローアップの質問で空白を埋める
4. ファイル書き込み前にプロポーザルを提示・確認

また、`CLAUDE_CODE_NEW_INIT=1` 時は `/init` が以下のファイルも読み込んでインポートする:
- `AGENTS.md`
- `.devin/rules/`
- `.windsurf/rules/` / `.windsurfrules`
- `.clinerules`

（通常の `/init` は Cursor rules と Copilot rules のみ読み込む）

### `claudeMd` キー in managed-settings.json

組織管理者が managed-settings.json に `claudeMd` キーで CLAUDE.md コンテンツを直接埋め込める。別ファイル展開不要になる。

```json
{
  "claudeMd": "Always run `make lint` before committing.\nNever push directly to main."
}
```

user / project / local 設定では無効（managed / policy 設定のみ有効）。

### `claudeMdExcludes`: CLAUDE.md の選択的除外

大規模モノレポで他チームの CLAUDE.md が読み込まれてしまう問題への対応。glob パターンで特定ファイルをスキップ可能。

```json
{
  "claudeMdExcludes": [
    "**/monorepo/CLAUDE.md",
    "/home/user/monorepo/other-team/.claude/rules/**"
  ]
}
```

- user / project / local / managed の全設定レイヤーで設定可能
- 配列は各レイヤーでマージされる
- managed policy の CLAUDE.md は除外不可（常に適用）

### `autoMemoryDirectory`: Auto Memory の保存場所カスタマイズ

```json
{
  "autoMemoryDirectory": "~/my-custom-memory-dir"
}
```

- 絶対パスまたは `~/` で始まるパスが必要
- project / local 設定で使用する場合はワークスペーストラストダイアログの承認が必要
- 全設定スコープで有効

### `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` 環境変数

`--add-dir` で追加した外部ディレクトリからも CLAUDE.md を読み込む:

```bash
CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 claude --add-dir ../shared-config
```

読み込まれる対象: `CLAUDE.md` / `.claude/CLAUDE.md` / `.claude/rules/*.md` / `CLAUDE.local.md`（`--setting-sources` で local 除外時は CLAUDE.local.md をスキップ）

### スキルの `disable-model-invocation: true`

副作用のあるワークフロースキルをモデル自動呼び出しから保護するフラグ。`true` に設定すると、Claude が状況に応じて自動的にスキルを呼び出すことがなくなり、明示的に `/skill-name` で呼び出した場合のみ実行される。

```yaml
---
name: deploy
description: Deploy to production
disable-model-invocation: true
---
```

### `InstructionsLoaded` フックで命令ファイルのデバッグ

`InstructionsLoaded` フックイベントを使うと、どの命令ファイルがいつ・なぜ読み込まれたかをログに記録できる（パス限定ルールや遅延読み込みファイルのデバッグに有用）。

```json
{
  "hooks": {
    "InstructionsLoaded": [{
      "type": "command",
      "command": "echo 'Loaded: $INSTRUCTIONS_PATH' >> /tmp/memory-debug.log"
    }]
  }
}
```

### AGENTS.md との互換性

Claude Code は `AGENTS.md` を直接読まない（`CLAUDE.md` を読む）。`AGENTS.md` がある場合は `CLAUDE.md` から `@AGENTS.md` でインポートするか、symlink を張ることが推奨される。

```bash
ln -s AGENTS.md CLAUDE.md
```
