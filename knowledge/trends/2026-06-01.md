## 前回（2026-05-25）からの新規判明事項

### 1. ビルトインサブエージェントに 2 種追加（公式ドキュメントに初登場）

前回レポートには Explore / Plan / general-purpose の 3 種が記載されていたが、公式ドキュメントに以下 2 種が追加記載された。

| サブエージェント | モデル | 用途 |
|----------------|--------|------|
| `statusline-setup` | Sonnet | `/statusline` 実行時にステータスライン設定を担当 |
| `claude-code-guide` | Haiku | Claude Code 機能について質問された場合の回答 |

また、Explore / Plan サブエージェントは **CLAUDE.md ファイルと親セッションの git status をスキップ**して実行されることが明確化（コスト削減のため）。カスタムサブエージェントは通常通り CLAUDE.md をロードする。

### 2. CLIフラグ `--agents` でセッションスコープのサブエージェントをJSON定義

ファイルを作成せずにサブエージェントをセッション単位で定義できる機能が正式ドキュメント化された。CI/CDスクリプトや一時的なテストに有効。

```bash
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

前回の `--agent <name>` フラグ（既存エージェントの指定）とは別機能。

### 3. プラグインエージェントのスコープ識別子（サブディレクトリパスが識別子に含まれる）

前回ドキュメントには「`@agent-my-plugin:review:security`」という記述があったが、その詳細が確認できた。

- プラグインの `agents/` ディレクトリ内のサブフォルダパスが識別子の一部になる
- 例: プラグイン `my-plugin` の `agents/review/security.md` → 識別子は `my-plugin:review:security`
- プロジェクト・ユーザースコープのサブエージェントはサブフォルダパスが識別子に含まれない（`name` フロントマターのみ）

### 4. SessionStart フックの新出力フィールド（3種）

`hookSpecificOutput` に以下の新フィールドが正式ドキュメント化された。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "sessionTitle": "auth-refactor",
    "initialUserMessage": "最初のプロンプトテキスト",
    "reloadSkills": true
  }
}
```

| フィールド | 機能 |
|-----------|------|
| `sessionTitle` | フックからセッション名を設定（`/rename` と同等） |
| `initialUserMessage` | セッション開始時の最初のメッセージを自動送信 |
| `reloadSkills` | フック実行後にスキルディレクトリを再スキャン |

### 5. `Setup` フックイベント（`--init-only` フラグ連携）

新フックイベント `Setup` が追加。`--init-only` フラグで一回限りの初期化処理に使用する。通常の SessionStart と異なり、初回セットアップ専用。

```json
{
  "hooks": {
    "Setup": [{
      "hooks": [{ "type": "command", "command": "first-time-setup.sh" }]
    }]
  }
}
```

### 6. フック型 `mcp_tool` の詳細確認

MCP サーバーのツールを直接呼び出すフック型として `mcp_tool` が正式ドキュメントに詳述された。

```json
{
  "type": "mcp_tool",
  "server": "my_server",
  "tool": "security_scan",
  "input": { "file_path": "${tool_input.file_path}" }
}
```

- ツールのテキスト出力は command フックの stdout と同様に扱われる
- 有効な JSON であれば decision として解析される

### 7. フックの並列実行と重複排除

- 同一イベントにマッチしたフックは**並列実行**される（公式確認）
- 同一ハンドラーが複数箇所で定義された場合、**自動的に重複排除**される

### 8. プロンプトフックの `model` フィールド

`prompt` タイプフックに `model` フィールドが追加。使用するモデルを指定可能。

```json
{
  "type": "prompt",
  "prompt": "このコマンドは安全ですか？",
  "model": "claude-opus-4-1",
  "timeout": 30
}
```

デフォルトタイムアウト: command は 600秒、prompt は 30秒。

### 9. パスプレースホルダーに `${CLAUDE_PLUGIN_DATA}` 追加

フックで使用できるプレースホルダーに新規追加。

| プレースホルダー | 内容 |
|----------------|------|
| `${CLAUDE_PROJECT_DIR}` | プロジェクトルート（既知） |
| `${CLAUDE_PLUGIN_ROOT}` | プラグインインストールディレクトリ（既知） |
| `${CLAUDE_PLUGIN_DATA}` | プラグインの永続データディレクトリ（**新規**） |

### 10. 新環境変数・CLIフラグ（メモリ関連）

| 変数/フラグ | 機能 |
|------------|------|
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` | Auto Memory を環境変数で無効化 |
| `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` | `--add-dir` で追加したディレクトリの CLAUDE.md もロード |
| `--append-system-prompt` | システムプロンプトに追記（スクリプト・自動化向け） |
| `--setting-sources` | ロードする設定ソースを指定（例: `local` を除外） |

### 11. `claudeMd` 設定キー（managed-settings.json 埋め込み）

managed-settings.json に CLAUDE.md の内容を直接埋め込める新設定キー。別ファイルをデプロイせずに組織全体のガイドラインを配布可能。

```json
{
  "claudeMd": "Always run `make lint` before committing.\nNever push directly to main."
}
```

- ユーザー・プロジェクト・ローカル設定では無効（マネージドポリシーのみ有効）
- 通常のマネージドポリシー CLAUDE.md と同等の優先度

### 12. 逆境的レビューパターン（Adversarial Review）がベストプラクティスに追加

公式ベストプラクティスに「Adversarial Review（敵対的レビュー）」パターンが追加された。

```text
# 実装後のレビュー手順
Use a subagent to review the rate limiter diff against PLAN.md.
Check that every requirement is implemented, the listed edge cases have tests,
and nothing outside the task's scope changed.
Report gaps, not style preferences.
```

- レビューをサブエージェントが独立コンテキストで実施（実装バイアスなし）
- ビルトインの `/code-review` スキルが同様の機能を提供
- **注意**: レビュアーを「ギャップを探す」よう誘導すると過剰エンジニアリングになる可能性。正確性・要件に関わるもののみレポートするよう指示すること

### 13. `--add-dir` ディレクトリはサブエージェントスキャン対象外

`--add-dir` で追加したディレクトリはファイルアクセスのみ許可される（設定のスキャン対象外）。サブエージェントを共有する場合は `~/.claude/agents/` またはプラグインを使用する必要がある。

### 14. /init の詳細な動作（CLAUDE_CODE_NEW_INIT=1）

- `CLAUDE_CODE_NEW_INIT=1` のインタラクティブフローが詳述
  - Phase 1: サブエージェントでコードベースを探索
  - Phase 2: フォローアップ質問で空白を埋める
  - Phase 3: 提案をレビュー後にファイル書き込み
  - 設定対象: CLAUDE.md、スキル、フック
- 既存 CLAUDE.md がある場合は上書きせず改善案を提案
