## 今週の新規発見（前回 2026-07-13 との差分）

### 1. `/doctor` コマンドの機能拡張（v2.1.206+）

**前回**: 重複サブエージェントファイルを検出してリネーム/削除を提案するのみ。

**今週確認**: CLAUDE.md のトリム提案機能が追加。コードベースから推測できるディレクトリ構成・依存リスト・アーキテクチャ概要などを削除提案し、ツールデフォルトと異なる落とし穴・根拠・規約のみを残すよう提案する。

```bash
/doctor  # セッション内で実行 → CLAUDE.md の肥大化を検出して削減提案
```

> 対象バージョン: **v2.1.206 以降**

---

### 2. プラグインフックの `${user_config.*}` 参照禁止（v2.1.207+）

シェル形式のプラグインフック（`args` 配列なしの command フック）から `${user_config.*}` 変数を参照できなくなった。exec 形式（`args` 配列あり）も同様。

影響範囲: プラグイン提供フックのみ。プロジェクト/ユーザーフックは影響なし。

---

### 3. 無効 glob パターンの挙動変更（v2.1.207+）

`.claude/rules/` のパス限定ルールで、`[` を含む無効な glob パターン（例: `photos [2024/**`）が、以前は Read ツール呼び出し時に**全エラー**を引き起こしていたが、v2.1.207 以降は**当該パターンがマッチなしになる**（他のパターンは継続動作）。

```markdown
---
paths:
  - "photos [2024/**"   # v2.1.207以前: この書き方が全ファイルの Read エラーを引き起こす
  - "*.md"              # v2.1.207以降: 上が無効でも *.md は正常にマッチし続ける
---
```

リテラルの `[` を使う場合はエスケープが必要: `photos \[2024/**`

---

### 4. MEMORY.md 書き込みサイズチェックの強化（v2.1.210+）

Auto Memory の `MEMORY.md` への書き込み後、Claude Code がファイルを **200行 / 25KB** の読み込み上限に対して測定する:

- **上限に近い場合**: Claude Code がリマインダーを返す（「1行1エントリに短縮し、詳細はトピックファイルへ移動、古いエントリをマージ/削除せよ」）
- **上限を超えた場合**: 書き込みは成功するが、Claude Code がエラーを返して「インデックスを書き直せ」と伝える（次回ロード時に超過分が切り捨てられるため）

> 対象バージョン: **v2.1.210 以降**

---

### 5. MEMORY.md のサイズ測定からフロントマター/コメント除外（v2.1.211+）

v2.1.210 で導入されたサイズチェックの測定対象が変更:

- **v2.1.210**: raw ファイルを測定 → YAML フロントマターや HTML コメントが上限に引っかかる可能性あり
- **v2.1.211 以降**: 読み込まれるコンテンツ（フロントマター・ブロックレベルコメントを除去後）を測定 → フロントマターやコメントが大きくても上限に影響しない

CLAUDE.md ファイルはこの制限がなく、長さにかかわらず全内容がロードされる（短い方が遵守率は高い）。

---

### 6. `isolation: worktree` のワーキングディレクトリチェック範囲拡張（v2.1.210+）

`isolation: worktree` サブエージェントのワーキングディレクトリ安全チェックが拡張:

- **v2.1.210 以前**: 起動ディレクトリ自身のみをチェック（同リポジトリ内の別ディレクトリは漏れた）
- **v2.1.210 以降**: 起動ディレクトリを含む**リポジトリ全体**を対象にチェック。セッションが worktree のリンク元であるメインチェックアウトも含む

実務への影響: モノレポのサブディレクトリで Claude Code を起動している場合、リポジトリルートへの意図しない書き込みを防止できるようになった。

---

### 7. `--setting-sources project` 除外の挙動修正（v2.1.211+）

`--setting-sources` で `project` を除外した場合の挙動が修正:

- **v2.1.211 以前**: パス限定ルール（`paths` frontmatter 付き）や、ネストした `.claude/rules/` ディレクトリのルールは、`project` を除外しても**ロードされ続けた**
- **v2.1.211 以降**: これらのルールも確実にスキップされる

用途: マルチプロジェクト環境で特定セッションからプロジェクト設定を完全除外したいケース（セキュリティ検証・クリーンなデフォルト動作テスト等）。
