## 今週の主要発見

### 1. サブエージェントのデフォルトネスト深さが 3 層（ドキュメント明確化）

公式サブエージェントドキュメントに次の記述が明確化された:

> By default, subagents can nest up to **3 layers deep** below main conversation.

我々の知識ベース（`docs/02_design-patterns.md`）では「最大5段階（v2.1.172+）」と記録していたが、この表現は誤りだった。正確には:

- **デフォルト**: 3レイヤー（メインセッションの下に3段まで）
- **設定変更**: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 環境変数で変更可能
- **無効化**: `1` に設定するとネスト完全無効
- v2.1.172+ で追加された機能は「最大5段階まで設定可能な仕組み」ではなく「デフォルト3段のネスト機能そのもの」

```json
{
  "env": {
    "CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "2"
  }
}
```

### 2. 同時実行サブエージェント数の上限が明文化

公式ドキュメントに以下が明記された:

- **デフォルト上限**: 20 同時サブエージェント
- **超過時の挙動**: 上限到達でスポーン失敗（エラー）
- **設定変更**: `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 環境変数で変更可能
- **例外**: `ultracode` 有効時はこの制限が免除される

```json
{
  "env": {
    "CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS": "50"
  }
}
```

これは大規模並列タスク（ファイル一斉マイグレーション等）の設計時に重要なパラメータ。

### 3. フォーク（/subtask）コマンドの公式確認

`/subtask` コマンドが公式サブエージェントドキュメントで説明された:

```
/subtask draft unit tests for the parser changes so far
```

`/fork` とは異なり `/subtask` は同じ目的（現在の会話履歴を継承したサブエージェント起動）のために使う。フォーク禁止は:

```json
{
  "permissions": {
    "deny": ["Agent(fork)"]
  }
}
```

### 4. バックグラウンドサブエージェントの利用可能ツールセットが明文化

バックグラウンドサブエージェント（fork mode ON）が利用できる built-in ツールが公式に列挙された:

- `Read`, `Grep`, `Glob`, `Bash`, `PowerShell`, `Edit`, `Write`, `NotebookEdit`
- `WebFetch`, `WebSearch`, `TodoWrite`, `Skill`, `ToolSearch`
- `EnterWorktree`, `ExitWorktree`, `Monitor`, `TaskStop`, `SendMessage`, `Artifact`

フォアグラウンドサブエージェントよりもツールセットが制限されるが、MCP ツールは引き続き利用可能。

### 5. ベストプラクティス: 検証手段の段階設計が公式整理

「Claude に自己検証させる」パターンの段階選択が公式ドキュメントに整理された:

| 強度 | 手段 | 特徴 |
|------|------|------|
| 軽量 | プロンプト内にテスト実行を含める | 即座・設定不要 |
| 中間 | `/goal` 条件（毎ターン評価） | LLM 評価・柔軟 |
| 強固 | `Stop` フック（スクリプト実行） | 決定論的・最大8回ブロック |
| 独立 | 検証サブエージェント | 新鮮コンテキスト・実装バイアスなし |
