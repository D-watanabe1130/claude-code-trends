## 今週の最大トピック：Claude 5 ファミリーが公式ドキュメントに登場

### サブエージェント `model` フィールドで `claude-opus-5` / `claude-sonnet-5` が公式例示

サブエージェントのドキュメントが更新され、`model` フィールドの説明に **フルモデル ID の例として `claude-opus-5` / `claude-sonnet-5`** が明記された。

```yaml
---
name: quality-reviewer
model: claude-opus-5   # フルモデルIDを直接指定
---
```

従来のエイリアス（`sonnet`, `opus`, `haiku`, `fable`）はそのまま使用可能。Claude 5 世代（Fable 5: `claude-fable-5`、Opus 5: `claude-opus-5`、Sonnet 5: `claude-sonnet-5`）が claude CLI の `--model` フラグと同じ形式で、サブエージェント定義に使用できることが公式に確認された。

## 今週の新規発見・変更点

### 1. `Ctrl+G` でプランをテキストエディタで直接編集（公式ベストプラクティスに明記）

プランモードの Plan ステップにおいて、`Ctrl+G` を押すと Claude が作成したプランをテキストエディタ（VS Code 等）で直接編集してから実装に進めることが公式ドキュメントに記載された。

**4段階ワークフロー（改訂版）:**

```
1. Explore（plan mode）: ファイル読み込み・調査
2. Plan（plan mode）: 実装計画作成 → Ctrl+G でエディタ編集可能
3. Implement（default mode）: コーディング＋テスト
4. Commit: コミット＆PR作成
```

`Ctrl+G` の活用場面:
- Claude の計画をそのまま受け入れず、スコープを絞りたい場合
- 計画の一部だけ修正して実装させたい場合
- チームでのペアプログラミング（人間が最終確認してから実行）

### 2. `--no-session-persistence` フラグが公式ドキュメントに明記

`claude -p "prompt"` による非インタラクティブ実行では**デフォルトでセッションが保存**され、後から `--continue` / `--resume` で再開できる。セッションを保存したくない場合は `--no-session-persistence` を渡す。

```bash
# セッション保存あり（デフォルト）
claude -p "analyze this code"

# セッション保存なし（CI/CD の使い捨て実行向け）
claude -p "analyze this code" --no-session-persistence

# 出力フォーマット詳細（今週公式明記）
# json: result フィールドを含む単一JSONオブジェクト
# stream-json: 1行1JSONオブジェクト（init イベントから開始）
claude -p "list API endpoints" --output-format json
claude -p "analyze logs" --output-format stream-json --verbose
```

### 3. フック共通入力フィールド `effort` がオブジェクト型として明文化

フックが受け取る JSON 入力の `effort` フィールドが、**文字列ではなくオブジェクト**型であることが公式ドキュメントに明記された。

```json
{
  "session_id": "abc123",
  "effort": { "level": "high" },
  "hook_event_name": "PreToolUse"
}
```

`effort.level` の値: `"low"` / `"medium"` / `"high"` / `"xhigh"` / `"max"`

（従来 `$CLAUDE_EFFORT` 環境変数として文書化されていたが、JSON 入力フィールドの型詳細が今週追加された）

### 4. `/context` コマンドの役割が明文化

CLAUDE.md が正常にロードされているかの確認方法として **`/context` コマンドを使う**方法が公式ベストプラクティスに明記された。

```text
/context   # ロード済みのメモリファイルリストと内容を確認
/memory    # ファイルを開いて編集・Auto Memory のトグル
```

`/context`: ロードされたファイル一覧＋内容を確認（デバッグ用）  
`/memory`: ファイルを編集するためのUI（CLAUDE.md や MEMORY.md のオープン）
