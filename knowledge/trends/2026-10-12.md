## 前回（2026-10-05）との差分

### 1. v2.1.295+: フックハンドラーに `onFailure: "block"` フィールド（NEW）

フックハンドラーが失敗（終了コード 2 以外のゼロでない終了）したとき、アクションをブロックできる新フィールドが追加された。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/policy-check.sh",
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
```

| 値 | 動作 |
|---|---|
| `"continue"`（既定） | 失敗しても警告のみ、アクションは続行 |
| `"block"` | 失敗時にアクションをブロック |

従来は設定ミスのポリシーフックがエラーで素通りしてしまう問題があったが、これにより確実にブロックできるようになった。

### 2. v2.1.296+: `CLAUDE_ENV_FILE` の PowerShell 対応（NEW）

`CLAUDE_ENV_FILE` で指定した環境変数ファイルが PowerShell 環境でも動作するようになった（v2.1.296+）。以前は Bash/Zsh のみの対応だった。`SessionStart` フックで環境変数を永続化するユースケースが Windows 環境でも利用可能になった。

### 3. 新フックタイプ 3 種のドキュメント化（NEW 確認）

以下の 3 つのフックハンドラータイプが公式ドキュメントに明記された（バージョン確定を要調査）:

| タイプ | 内容 |
|---|---|
| `mcp_tool` | 設定済み MCPサーバーのツールをフックハンドラーとして直接呼び出す |
| `prompt` | Claude モデルに単発評価を依頼し、JSON で判定結果を返す |
| `agent` | サブエージェントを起動して条件を検証する（**実験的**） |

`mcp_tool` の設定例:
```json
{
  "type": "mcp_tool",
  "server": "plugin:my-plugin:db-server",
  "tool": "validate_query",
  "input": { "query": "${tool_input.command}" }
}
```

### 4. `/goal` コマンドの公式ドキュメント化（NEW 確認）

ベストプラクティスドキュメントに `/goal` コマンドが明記された。ゴール条件を設定すると別の評価ループが毎ターン後にチェックし、ゴールが解決するまで Claude が作業を継続する。

- `/goal` 条件として設定 → 毎ターン後に自動評価・継続
- Claude が行き詰まった場合はランを停止し、ゴールは未解決のまま保持
- 無人実行で「完了するまで自律的に作業させる」シナリオに適用

### 5. `/btw` コマンドの公式ドキュメント化（NEW 確認）

コンテキストに影響を与えない「サイドクエスチョン」コマンドとして `/btw` が公式ドキュメントに記載された。

```
/btw Reactのuseffectってクリーンアップ関数返す必要ある？
```

回答が会話履歴に入らないため、コンテキストを汚染せずに手軽な確認が可能。

### 6. `/compact <instructions>` による圧縮指示の明示化（NEW 確認）

`/compact` コマンドにカスタム指示を渡せることが公式ベストプラクティスに記載された。

```
/compact Focus on the API changes
```

さらにリワインドメニューに 2 種の部分要約オプションが追加されていることが確認された:

| オプション | 動作 |
|---|---|
| **Summarize from here** | 選択メッセージ以降を要約、以前のコンテキストはそのまま |
| **Summarize up to here** | 選択メッセージまでを要約、以降の最近の会話はフルで保持 |

### 7. `CLAUDE_CODE_NEW_INIT=1` 環境変数（NEW 確認）

`/init` コマンドのインタラクティブな多段階フローを有効化する環境変数が公式ドキュメントに記載された。

```bash
CLAUDE_CODE_NEW_INIT=1 claude
# → /init 実行時に CLAUDE.md / skills / hooks をどれ作るか選択
# → サブエージェントでコードベース探索 → 質問で補足 → 提案をレビューして書き込み
```

通常の `/init` はコードベースを読んで即書き込みするが、このモードでは提案前にレビューが可能。

### 8. フックの `args` フィールドによる exec 形式実行（NEW 確認）

フックハンドラーの `command` に `args` フィールドを付けると、シェルを経由しない exec 形式で実行できることが明記された。スペースや特殊文字を含むパスを安全に扱える。

```json
{
  "type": "command",
  "command": "/path/to/my hook/script.sh",
  "args": ["--arg1", "${tool_input.file_path}"]
}
```

**注意**: Windows では `.cmd`/`.bat` を直接指定できないため `node` 経由が推奨。

### 9. CLAUDE.md の HTML コメント除去（NEW 確認）

CLAUDE.md のブロックレベル HTML コメント（`<!-- ... -->`）はコンテキストに注入される前に除去されることが公式ドキュメントに明記された。メンテナ向けのメモをコンテキストトークンを消費せずに記述できる。コードブロック内のコメントは除去されない。

## 今週のホットトピック

1. **`onFailure: "block"` でポリシーフックの設定ミスを防止（v2.1.295+）**: これまでフック自体がエラー終了した場合はポリシーチェックが素通りしていた。`onFailure: "block"` により設定ミスでも安全側に倒せる。セキュリティ用途のフックに強く推奨される設定。

2. **3 種のフックタイプ（`mcp_tool` / `prompt` / `agent`）公式化**: フックのロジックを Shell スクリプトのみでなく MCP ツール・AI 評価・サブエージェントとして記述できるようになり、ポリシー記述の柔軟性が大幅に向上。

3. **コンテキスト管理の精緻化（`/btw`・部分要約・`/compact <instructions>`）**: コンテキストを汚染せずに確認する `/btw`、ピンポイントで要約箇所を選べるリワインドの 2 オプション、圧縮指示付き `/compact` により、長期セッションのコンテキスト管理がより細かく制御できるようになった。

## 設計パターンへの示唆

### ポリシーフックの安全化パターン（v2.1.295+）

`onFailure: "block"` を全ポリシー系フックに設定し、スクリプトのバグや環境差異による素通りを防止する:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/security-check.sh",
            "args": [],
            "onFailure": "block",
            "statusMessage": "セキュリティチェック中..."
          }
        ]
      }
    ]
  }
}
```

### MCP ツールによるフックハンドラーパターン

ツール呼び出し前に MCP サーバーのバリデーターを呼び出し、データベースクエリなど外部ステートを使った判定を行う:

```json
{
  "type": "mcp_tool",
  "server": "my-validator",
  "tool": "check_allowed",
  "input": {
    "tool": "${hook_event_name}",
    "command": "${tool_input.command}"
  }
}
```
