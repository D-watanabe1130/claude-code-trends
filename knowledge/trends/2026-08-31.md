## 今週の主要新規発見

### 1. サブエージェント: `maxTurns` フィールド（v2.1.246+）

```yaml
---
name: bounded-researcher
description: 調査タスクをターン数制限付きで実行
maxTurns: 10
---
```

- サブエージェントが停止するまでの最大エージェントターン数を制限
- `maxTurns` に達したサブエージェントは「partial」としてマークされ、Claude が継続を指示可能
- 暴走防止・コスト管理に有効

### 2. サブエージェント: 実験的 `cacheTtl` オプション（v2.1.248+）

```yaml
---
name: cached-agent
experimental:
  cacheTtl: 5m   # または 1h
---
```

- プロンプトキャッシュの TTL を実験的にオーバーライド可能
- `5m`（5分）または `1h`（1時間）を指定
- 頻繁に呼ばれるサブエージェントのキャッシュヒット率向上に有効

### 3. サブエージェント: MCP サーバー信頼要件の変更（v2.1.238+）

以前は全 MCP サーバー参照にフォルダトラストが必要だったが、v2.1.238+ で細分化：

| 定義場所 | 信頼要件 |
|---------|---------|
| `.claude/agents/` のインライン定義 | **フォルダトラスト必須** |
| 既存セッション接続への参照 | 不要 |
| `~/.claude/agents/` のユーザーレベル定義 | 不要 |
| CLI 定義・マネージド設定 | 不要 |

### 4. フック: `PreModelSwitch` / `PostModelSwitch` イベント（新規確認）

| イベント | ブロック | マッチャー例 |
|---------|---------|------------|
| `PreModelSwitch` | **Yes（exit 2 でモデル切り替え阻止）** | `claude-opus-5`, `claude-opus-4-6\|claude-opus-5` |
| `PostModelSwitch` | No | 同上 |

```json
{
  "hooks": {
    "PreModelSwitch": [
      {
        "matcher": "claude-haiku-4-5-20251001",
        "hooks": [{ "type": "command", "command": "block-haiku-switch.sh" }]
      }
    ]
  }
}
```

モデル切り替えを制御・監査できる。企業ポリシーでのモデル使用管理に活用可能。

### 5. フック: `SessionStart` マッチャーに `fork` 追加

`SessionStart` フックのマッチャーに新たに `fork` が公式確認された：

| ソース値 | 意味 |
|---------|------|
| `startup` | 新規セッション開始 |
| `resume` | セッション再開 |
| `clear` | `/clear` によるリセット後 |
| `compact` | `/compact` 後の再開 |
| `fork` | **（新規確認）** フォークによる開始 |

### 6. フック: `Notification` マッチャーの追加値

既知（`permission_prompt`, `idle_prompt`, `auth_success`）に加えて以下が公式確認：

- `elicitation_dialog`: MCP サーバーが入力要求を出したとき
- `quota_auto_resume_fired`: クォータ制限後の自動再開時

### 7. フック: `disableAllHooks` 設定とCLIオーバーライド

```json
{
  "disableAllHooks": true
}
```

- settings.json に設定するとそのスコープのフックを全無効化
- CLI で一時的にオーバーライド: `claude --settings '{"disableAllHooks": true}'`
- **マネージドポリシーのフックはユーザー/プロジェクトの `disableAllHooks` では無効化不可**（マネージドレベルの設定のみが無効化できる）

### 8. フック: HTTP フックアロウリスト（組織制御）

新規確認された組織レベルの HTTP フック制御設定：

```json
{
  "allowedHttpHookUrls": ["https://api.company.com/*"],
  "httpHookAllowedEnvVars": ["CI_TOKEN", "GITHUB_TOKEN"]
}
```

- `allowedHttpHookUrls`: 全ソース（user/project/local/plugin）のフックに適用。URL がマッチしないフックはスキップされる
- `httpHookAllowedEnvVars`: フックヘッダーで使用できる環境変数の allowlist
- 両設定は複数スコープをまたいでマージされる

### 9. ベストプラクティス: `/verify` コマンド

公式ベストプラクティスドキュメントに明記：

> Run `/verify` yourself after Claude's check passes to confirm the change against the running app.

Claude の自己チェック（テスト・ビルド等）が通った後、ユーザー自身が実際のアプリ上で `/verify` を使って最終確認するワークフローが公式推奨。

### 10. ベストプラクティス: `--permission-mode plan` CLI フラグ

```bash
claude --permission-mode plan
```

セッション開始時からプランモードで起動する CLI フラグが公式ドキュメントに明記。インタラクティブに `Shift+Tab` で切り替えなくても、プランモードからセッションを開始できる。

### 11. サブエージェント出力スキャン詳細（v2.1.210+）

前週まで知識ベースに未記録だった詳細が確認された：

- **バックスラッシュ挿入**: `<system-reminder>` 等のシステムタグを模倣するテキストにバックスラッシュを挿入してエスケープ
- **マーカー行**: パーミッション設定やシステムタグを模倣するパターンが検出された場合、`[harness: subagent output matched instruction-shaped pattern(s):]` というマーカー行を先頭に付与
- **コンテンツは削除しない**: 検出されてもコンテンツは保持される。誤解釈を防ぐための処理のみ
