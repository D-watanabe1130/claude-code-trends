## 今週の主要新発見（前回比 2026-06-08 初回との差分）

### 1. Opus 4.8 リリース（v2.1.154）

新モデル **Opus 4.8** が正式リリース。デフォルトで `high` エフォートで動作し、`/effort xhigh` で最も困難なタスクに対応。

```bash
# Fast Modeがフラクションコスト（以前の2倍レート → 2.5x速度）
/fast   # Opus 4.8での高速モード
/effort xhigh  # 最大努力レベル（xhigh）
```

- **Fast Mode on Opus 4.8**: 標準レートの2倍のコストで2.5倍の速度
- `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` は廃止（v2.1.160で削除）
- v2.1.154より、Haiku/Sonnet/Opus 4.7以前以外のモデルで「リーンシステムプロンプト」がデフォルト

### 2. ダイナミックワークフロー（Dynamic Workflows）（v2.1.154）

数十〜数百のバックグラウンドエージェントを並列オーケストレーションする新機能。

```bash
# キーワードでトリガー（"ultracode"）
/effort ultracode

# ワークフロー一覧
/workflows
```

- v2.1.160でトリガーキーワードが `workflow` → `ultracode` に変更
- `.claude/workflows/` ディレクトリでワークフローを管理
- Deep Research などのバンドルワークフローが利用可能

### 3. fallbackModel 設定（v2.1.166）

プライマリモデルが過負荷・利用不可の場合に試みるフォールバックモデルを最大3つ設定可能。

```json
{
  "fallbackModel": ["claude-sonnet-4-5", "claude-haiku-4-5"]
}
```

- `--fallback-model` CLIフラグでインタラクティブセッションにも適用
- 非リトライ可能なAPIエラー時に自動的にフォールバックモデルで1回リトライ（v2.1.166）

### 4. requiredMinimumVersion / requiredMaximumVersion（v2.1.163）

組織管理者がバージョン範囲外の Claude Code の起動を拒否できる managed-settings キー。

```json
{
  "requiredMinimumVersion": "2.1.150",
  "requiredMaximumVersion": "2.1.200"
}
```

バージョンが許可範囲外の場合、Claude Code は起動を拒否してユーザーに修正を案内する。

### 5. Stop/SubagentStop フックの additionalContext（v2.1.163）

Stop・SubagentStop フックが `additionalContext` を返すことで、エラー扱いにならずにClaudeへフィードバックを与えてターンを継続できるようになった。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "Stop",
    "additionalContext": "Tests failed: 3 errors. Please fix before finishing."
  }
}
```

これにより Stop フックが純粋なブロックゲートだけでなく、コンテキストを追加してClaudeを誘導するガイドとしても機能できる。

### 6. スキルの `\$` エスケープ構文（v2.1.163）

スキルのコマンド本文で `\$` を使うと、数字の前にリテラル `$` を含められる。

```markdown
# スキルコマンド内で
\$1 = first argument (リテラル $1 として解釈)
```

### 7. /plugin list コマンド（v2.1.163）

```bash
/plugin list            # インストール済みプラグイン一覧
/plugin list --enabled  # 有効なプラグインのみ
/plugin list --disabled # 無効なプラグインのみ
```

### 8. .claude/skills ディレクトリの自動ロード（v2.1.157）

プラグインがインストールされていなくても、`.claude/skills` ディレクトリに置いたプラグインが自動ロードされる。

```bash
claude plugin init <name>  # .claude/skills に新しいプラグインをスキャフォールド
```

### 9. claude agents --json の waitingFor フィールド（v2.1.162）

```bash
claude agents --json  # 各セッションに waitingFor が追加
```

`waitingFor` フィールドが待機中のセッションが何をブロックされているか示す（例: permission prompt）。

### 10. AUTO MODE の拡大（v2.1.158/v2.1.160）

- **Bedrock/Vertex/Foundry** でも Auto Mode が利用可能に（Opus 4.7/4.8、`CLAUDE_CODE_ENABLE_AUTO_MODE=1` でオプトイン）
- **VSCode** で Auto Mode がバイパスパーミッション設定なしでも利用可能に

### 11. シェルスタートアップファイルへの書き込み確認（v2.1.160）

`.zshenv`, `.zlogin`, `.bash_login` や `~/.config/git/` への書き込みに確認プロンプトが追加。意図せぬコマンド実行を防ぐ安全策。

`acceptEdits` モードでも `.npmrc`, `.yarnrc*`, `bunfig.toml`, `.bazelrc`, `.pre-commit-config.yaml`, `.devcontainer/` など、コード実行を許可するビルドツール設定ファイルへの書き込み前に確認を要求。

### 12. SendMessage のクロスセッションメッセージング強化（v2.1.166）

他の Claude セッションから `SendMessage` でリレーされたメッセージはユーザー権限を持たなくなった（セキュリティ強化）:
- 受信側はリレーされた権限リクエストを拒否
- Auto モードではリレーメッセージをブロック

### 13. `MAX_THINKING_TOKENS=0` で思考無効化（v2.1.166）

```bash
MAX_THINKING_TOKENS=0 claude        # 思考を無効化
--thinking disabled                  # CLIフラグでも可
```

デフォルトで思考するモデル（Opus 4.8等）でも API 経由で思考を無効化できる。

### 14. glob パターンの deny ルール（v2.1.166）

```json
{
  "deniedTools": ["*"]  // 全ツールを拒否
}
```

deny ルールのツール名位置で glob パターン（`"*"`）がサポートされた。allow ルールでは非 MCP glob は拒否される。

## エコシステムトレンド分析

1. **モデルの急速進化**: Opus 4.8（2.5x速度のFast Mode）→ Opus 4.9へのロードマップが示唆。高性能モデルでの高速実行がコスト競争力のポイントに。
2. **ダイナミックワークフロー**: 数百エージェントの並列実行が1コマンドで可能になりつつある。個人の生産性から組織のスケール問題解決へ。
3. **セキュリティ強化の継続**: クロスセッションメッセージング制限、シェルスタートアップファイル確認、managed-settings バージョン管理等、エンタープライズ採用を見据えたセキュリティ強化が進んでいる。
4. **クロスモデル統合**: Agent SDK + Plugin + MCP + Router の4方式でClaude Codeと他モデルを統合するエコシステムが成熟。
5. **フォールバック設計**: `fallbackModel`の公式サポートは信頼性を重視する本番運用への移行を示す。
