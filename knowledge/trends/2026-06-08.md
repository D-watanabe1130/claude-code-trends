## 今週の主要新発見（前回比 2026-06-01 との差分）

### 1. フォーク機能の正式デフォルト化（v2.1.161+）

`/fork` コマンドが v2.1.161 からデフォルト有効となった。以前は実験的機能として `CLAUDE_CODE_FORK_SUBAGENT=1` 環境変数が必要だったが、この変数は明示的な無効化 (`=0`) にのみ使用する形に変わった。段階的ロールアウトによりインタラクティブセッションでもデフォルト有効になる可能性がある。

```bash
# 明示的に無効化する場合
CLAUDE_CODE_FORK_SUBAGENT=0 claude
```

**フォーク観察パネル**（新機能）: 実行中のフォークがプロンプト下部のパネルに表示される。キー操作：
- `↑` / `↓`: 行を移動
- `Enter`: 選択したフォークのトランスクリプトを開き、追加メッセージを送信
- `x`: 完了したフォークを閉じる、または実行中を停止
- `Esc`: プロンプト入力にフォーカス戻す

### 2. Agent フック型（実験的）

新たな5つ目のフック型 `"type": "agent"` が追加された。検証用サブエージェントをフックから直接スポーンできる。

```json
{
  "type": "agent",
  "prompt": "Verify: $ARGUMENTS",
  "model": "claude-opus-4-8",
  "timeout": 60,
  "statusMessage": "..."
}
```

- Read、Grep、Glob ツールを利用可能
- 実験的機能のため将来変更の可能性あり
- タイムアウトデフォルト: 60秒

### 3. 新規フックイベント（大幅追加）

前回確認していた30種のフックイベントに加え、以下が今回の詳細調査で確認された：

| イベント | トリガー |
|---------|--------|
| `MessageDisplay` | アシスタントメッセージのテキストストリーミング中 |
| `Elicitation` | MCPサーバーがユーザー入力を要求したとき |
| `ElicitationResult` | ユーザーがMCP elicitationに応答した後 |
| `TeammateIdle` | Agent Team のチームメイトがアイドル状態になる直前 |
| `WorktreeCreate` | `--worktree` でワークツリーが作成されたとき |
| `WorktreeRemove` | ワークツリーが削除されたとき |
| `PostCompact` | コンテキスト圧縮完了後（`PreCompact` とは別） |
| `StopFailure` | APIエラーでターンが終了したとき（`rate_limit`, `authentication_failed` でマッチ可） |
| `TaskCreated` | `TaskCreate` でタスクが作成されたとき |
| `TaskCompleted` | タスクが完了マークされたとき |
| `UserPromptExpansion` | ユーザーコマンドがプロンプトに展開されるとき |

**MessageDisplay フック**の特筆点: `displayContent` フィールドで表示テキストを上書きできる（会話履歴には影響しない）。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "MessageDisplay",
    "displayContent": "改変後の表示テキスト（画面のみ）"
  }
}
```

**Elicitation/ElicitationResult フック**の新フィールド:
```json
{
  "hookSpecificOutput": {
    "hookEventName": "Elicitation",
    "action": "accept|decline|cancel",
    "content": { "field1": "value" }
  }
}
```

### 4. Stop フックの「決定論的ゲート」詳細仕様

`Stop` フックをチェックが通るまでターン終了をブロックする「決定論的ゲート」として使用できる仕様が公式に明確化された。**8回連続ブロックでClaudeCodeが強制的にオーバーライドして終了**する安全弁が存在する。

```text
1ターン内でのチェック段階選択:
- プロンプト内: テストを実行してイテレートするよう指示
- /goal 条件: ターン終了後も評価サブエージェントが再チェック
- Stop フック（決定論的）: スクリプトがcheckを実行し、通過するまでブロック（最大8回）
- 検証サブエージェント: フレッシュコンテキストで独立評価
```

### 5. イベント別タイムアウトのデフォルト値の差異

イベント種別によってフックのデフォルトタイムアウトが異なることが明確化された：

| イベント | command/http/mcp_tool | prompt | agent |
|---------|----------------------|--------|-------|
| デフォルト | 600秒 | 30秒 | 60秒 |
| `UserPromptSubmit` | **30秒** に短縮 | — | — |
| `MessageDisplay` | **10秒** に短縮 | — | — |

### 6. フック入力の新フィールド

全フックの受信 JSON に `agent_id` と `agent_type` フィールドが追加され、サブエージェントコンテキストを識別できるようになった：

```json
{
  "session_id": "abc123",
  "hook_event_name": "PreToolUse",
  "agent_id": "optional-subagent-id",
  "agent_type": "optional-agent-name",
  "effort": { "level": "high" }
}
```

環境変数 `CLAUDE_EFFORT` もフック内で利用可能になった。

### 7. 詳細化されたフックブロック可否マッピング

Exit code 2 でブロックできるイベントとできないイベントの完全なマッピングが公式ドキュメントに追加された：

**ブロック可能（exit 2 でアクションを防止）**:
- `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `UserPromptExpansion`, `Stop`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `ConfigChange`, `PreCompact`, `PostToolBatch`

**ブロック不可（exit 2 でも stderr 表示のみ）**:
- `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `Notification`, `SubagentStart`, `SessionStart`, `Setup`, `SessionEnd`, `CwdChanged`, `FileChanged`, `PostCompact`, `WorktreeRemove`, `InstructionsLoaded`, `StopFailure`, `MessageDisplay`

**特殊**:
- `WorktreeCreate`: 非ゼロ終了コードで作成失敗（ブロック扱い）

### 8. サブエージェントの新環境変数

```bash
# サブエージェントのモデルを環境変数で一括オーバーライド
CLAUDE_CODE_SUBAGENT_MODEL=claude-haiku-4-5-20251001 claude

# サブエージェントの自動圧縮しきい値をカスタマイズ（デフォルト95%）
CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70 claude

# バックグラウンドタスク機能を完全無効化
CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1 claude
```

### 9. サブエージェント自動圧縮

サブエージェントが独自の自動圧縮をサポートするようになった（メイン会話と同じロジック）。デフォルトで約95%容量到達時にトリガー。圧縮イベントはトランスクリプトに記録：

```json
{
  "type": "system",
  "subtype": "compact_boundary",
  "compactMetadata": {
    "trigger": "auto",
    "preTokens": 167189
  }
}
```

### 10. 管理者向けサブエージェント（Managed Subagents）

組織管理者が全ユーザー向けにサブエージェントを展開できる仕組みが確認された。優先度は最高（セッションスコープ・プロジェクト・ユーザーより上）：

| スコープ | 場所 | 優先度 |
|---------|------|--------|
| Managed settings | managed settings の `.claude/agents/` | 1（最高） |
| `--agents` フラグ | 現在のセッションのみ | 2 |
| `.claude/agents/` | プロジェクト | 3 |
| `~/.claude/agents/` | 全プロジェクト | 4 |
| プラグイン `agents/` | プラグイン有効時 | 5（最低） |

### 11. Task ツールから Agent ツールへの改名（v2.1.63）

`Task` ツールが `Agent` に改名された（v2.1.63）。既存の `Task(...)` 参照は後方互換エイリアスとして継続動作する。今後の新規コードでは `Agent(...)` 構文を使用すること。

```yaml
# 旧（引き続き動作）
tools: Task(worker, researcher), Read, Bash

# 新（推奨）
tools: Agent(worker, researcher), Read, Bash
```

### 12. サブエージェントのトランスクリプト管理

サブエージェントのトランスクリプトはメイン会話から独立して管理される：

- **保存場所**: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{id}.jsonl`
- **自動クリーンアップ**: `cleanupPeriodDays` 設定（デフォルト: 30日）
- **メイン会話の圧縮の影響を受けない**
- **セッション再開後も resumable**（同じセッションを再開することで）

### 13. サブエージェントファイルの即時ロード条件

サブエージェントファイルをディスク上で直接編集した場合、**セッション再起動が必要**。`/agents` インターフェース経由で作成・編集した場合は**再起動不要で即時反映**。

### 14. skills フィールドの挙動詳細

`skills` フロントマターフィールドの仕様が明確化された：

- `disable-model-invocation: true` が設定されたスキルはプリロード不可
- プリロードされていないスキルでも Skill ツールでの実行時呼び出しは可能
- `disallowedTools` に `Skill` を追加するとスキル呼び出しを完全に無効化できる
- `skills` でのプリロード = サブエージェントがコンテキストを制御；スキルの `context: fork` = スキルが指定エージェントにコンテンツを注入（同じ基盤システムの逆方向操作）

### 15. CLAUDE.md のアーキテクチャ明確化

CLAUDE.md がシステムプロンプトの一部ではなく、**システムプロンプトの後のユーザーメッセージとして注入**されることが公式ドキュメントに明記された。これは指示の遵守がシステムプロンプトより若干弱い理由を説明する重要な仕様情報。

厳密に守らせたい指示には `--append-system-prompt` フラグ（毎回渡す必要あり、スクリプト・自動化向き）またはフックを使用する。

### 16. 圧縮後のサバイバル仕様

`/compact` 後に何が復元されるかの詳細仕様が確認された：

- **プロジェクトルートの CLAUDE.md**: ✅ 圧縮後にディスクから再読み込み・再注入される
- **サブディレクトリのネストされた CLAUDE.md**: ❌ 自動再注入されない（そのサブディレクトリのファイルを次に読み込むまで待機）
- **Auto Memory MEMORY.md**: ✅ セッション開始時に読み込まれ、以降も保持

実用的影響: 重要な指示はネストされた CLAUDE.md ではなくプロジェクトルートの CLAUDE.md に置くこと。

### 17. 公式ベストプラクティスに「よくある失敗パターン」が追加

今週の調査で、公式 best-practices ドキュメントに以下の失敗パターンが明示的に追加・詳細化されていることを確認：

| パターン | 症状 | 対処 |
|---------|------|------|
| キッチンシンクセッション | 無関係なタスクを同一セッションで混在 | タスク間に `/clear` |
| 繰り返し修正 | 同じミスを2回以上修正 | 2回失敗したら `/clear` してより具体的なプロンプトで再開 |
| 過剰指定CLAUDE.md | 長すぎて重要ルールが埋もれる | 削除して不要な行を除去。フックに移行 |
| 信頼→検証ギャップ | エッジケースなしの一見もっともな実装 | テスト・スクリプト・スクリーンショットで必ず検証 |
| 無限探索 | 数百ファイルを読み込みコンテキストが満杯に | 調査スコープを絞るかサブエージェントを使用 |

### 18. CLAUDE_CODE_NEW_INIT=1 のインタラクティブ /init

`CLAUDE_CODE_NEW_INIT=1` を設定すると `/init` がインタラクティブなマルチフェーズフローになる：

1. サブエージェントがコードベースを探索
2. フォローアップ質問でギャップを補完
3. 設定内容（CLAUDE.md、スキル、フック）の提案を提示
4. ユーザーが確認後にファイル書き込み
